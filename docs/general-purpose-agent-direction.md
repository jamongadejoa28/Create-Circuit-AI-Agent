# 범용 KiCad 회로 설계 에이전트 전환 계획

## 1. 결론

이 프로젝트의 제품 목표는 `BLDC 보드 생성기`가 아니라, 사용자의 자연어 요구를
검토 가능한 KiCad 프로젝트로 바꾸는 **범용 회로 설계 보조 에이전트**다. BLDC,
STM32G474, DRV8311 규칙은 범용 엔진을 검증하는 한 사례이며 코어 동작의 전제가
되어서는 안 된다.

최근 구현 중 계층 시트, 충돌 검사 라우팅, ERC/렌더/넷리스트 검증은 범용 코어로
유지한다. 반면 특정 부품명을 검사하는 완성 규칙과 특정 보드 점수만으로 품질을
판정하는 방식은 플러그인 지식 및 다분야 평가 계층으로 격리한다.

## 2. 목표 아키텍처

```text
사용자 요구
  -> 요구사항 계약(역할, 수량, 전원, 인터페이스, 제약, 미결정 항목)
  -> 기능 블록 계획(전원/제어/센서/통신/구동 등 의미 기반 소유권)
  -> 부품 검색 + 근거 검색
  -> 블록별 회로 IR 합성
  -> 기능 완전성 게이트
  -> 결정론적 일반 정규화
  -> 적용 가능한 기기/회로군 규칙
  -> 계층/배치/안전 라우팅
  -> self ERC -> KiCad ERC -> SVG 시각 QA -> 넷리스트 왕복
  -> 결과 + 미해결 항목 + 근거
```

핵심 경계는 다음과 같다.

- LLM은 요구 해석, 블록 제안, 후보 중 선택, 제한된 연결 판단을 담당한다.
- 코드는 수량, 허용 부품/핀, 전기적 충돌, 좌표 안전성, 파일 형식과 결과 검증을
  담당한다.
- 데이터시트 기반 기기 규칙은 코어에 뒤섞지 않고 적용 조건과 출처가 있는 규칙
  팩으로 관리한다.
- 카탈로그에 소자가 없으면 명시적인 Conceptual 심볼을 사용한다. 비슷해 보이는
  잘못된 실제 부품으로 대체하지 않는다.

## 3. 이번에 고친 잘못된 성공 조건

ERC는 존재하는 회로의 전기적 오류를 찾지만, 사용자가 요구한 기능이 통째로
사라진 것은 알 수 없다. 실제 BLDC 실행에서 MCU 블록 합성이 토큰 한도로 실패한
뒤 MCU 없는 보드가 생성된 것이 이 문제다.

`validate_block_template()` 기능 완전성 게이트를 실제 Agent 실행 경로에 추가했다.
각 블록의 선언된 역할마다 합성 프롬프트에 제공한 카탈로그 후보 중 하나가 실제
IR에 존재해야 한다. 후보가 없던 역할은 명시적 Conceptual 심볼이 있어야 한다.
검사에 실패하면 블록을 한 번 새로 합성하며, 다시 실패하면 불완전한 보드를
내보내지 않고 `functional-completeness` 단계에서 중단한다. 이 검사는 MCU나 BLDC
문자열을 사용하지 않으므로 센서, 오디오, 전원, USB 등 모든 블록에 동일하게
작용한다.

## 4. 범용성과 특례의 분리 기준

### 범용 코어

- 요구 역할과 수량 보존
- 반복 블록 인스턴스화와 넷 네임스페이스
- 기능별 계층 시트 분할
- 핀/심볼/풋프린트 존재 검사
- 전원 입력/출력 ERC와 PWR_FLAG 처리
- 2노드 실제 배선 및 장애물 회피
- 라우팅 불가 시 올바른 라벨 폴백
- 시트 경계, 겹침, 텍스트 가독성 검사
- KiCad CLI 기반 ERC, 렌더링, 넷리스트 왕복

### 데이터시트 규칙 팩

- 특정 MCU의 실제 Alternate Function 핀맵
- 특정 드라이버의 MODE, charge-pump, current-sense 회로
- 특정 센서의 TEST/NC 및 전원 조건
- 특정 트랜시버의 모드 핀과 종단 회로

규칙 팩은 `applies()` 조건, 변환 동작, 출처, 검증 테스트를 가져야 한다. 규칙이
없는 부품은 LLM+RAG 결과와 일반 검증으로 처리하고, 확실하지 않은 연결은 사용자
미결정 항목으로 남긴다.

## 5. 배선 정책

- 같은 기능 시트의 짧은 로컬 연결은 실제 직교 와이어를 우선한다.
- 아날로그 피드백, 분압, 필터, 레귤레이터 보상망은 `필수 완결 토폴로지`로
  분류하고 라벨만으로 성공 처리하지 않는다.
- MCU/FPGA처럼 핀이 많은 디지털 허브는 데이터시트 기본 AF 매핑 또는 사용자
  핀맵이 있으면 연결하고, 그렇지 않으면 명명된 포트/라벨과 미결정 핀 표를 낸다.
- 시트 간 신호는 계층 포트 또는 전역 신호 정책을 사용한다.
- 3노드 이상 로컬 신호는 다음 구현 대상인 정션 트리 라우터가 담당한다. 구현 전
  무리하게 긴 선을 긋는 대신 안전한 라벨 폴백을 유지한다.

## 6. 평가 방식 전환

한 개의 BLDC 프롬프트를 여러 번 실행한 ERC 평균은 모델 편차와 특정 규칙 효과는
보여 주지만 범용 제품 품질을 증명하지 못한다. 릴리스 게이트는 최소 다음 회로군을
포함해야 한다.

1. 수동소자: LED, 버튼, 분압기, RC 필터
2. 아날로그: op-amp 증폭/필터, 비교기
3. 전원: LDO, buck, 보호 입력
4. 센서 버스: I2C, SPI, UART
5. 디지털 제어: MCU 최소 회로와 디버그 헤더
6. 통신: CAN, RS-485, USB 보조 회로
7. 구동: MOSFET, 모터/솔레노이드 드라이버
8. 카탈로그 부재: Conceptual 모듈 폴백

각 항목은 다음을 별도로 측정한다.

- 요구 역할/수량 충족률
- 필수 토폴로지 충족률
- self ERC와 KiCad ERC
- 넷리스트 왕복 일치
- 실제 로컬 와이어 비율과 라벨 폴백 비율
- 시각 QA 및 시트 경계 위반
- 근거 없는 자동 연결 수
- 동일 입력 반복 실행의 분산

## 7. 구현 순서

1. **완료:** 요구 역할 누락을 막는 블록 기능 완전성 게이트와 재시도/중단 정책
2. 부품별 정규화 함수를 출처 포함 규칙 레지스트리로 이동
3. 역할 이름을 자유 문자열이 아닌 기능 taxonomy + 사용자 원문으로 이중 저장
4. **1차 완료:** 아날로그 피드백/레귤레이터 바이패스 토폴로지 관찰기와 계약 평가
5. 3노드 이상 정션 트리 라우터 및 시트별 와이어 커버리지 보고
6. **1차 완료:** 위 8개 회로군의 고정 평가셋과 다중 seed 실행 하네스 구축
7. 평가 결과를 기준으로 RAG 청크, 모델, 규칙 팩을 각각 독립 개선

우선순위는 2번보다 3~6번의 측정 기반을 먼저 완성하는 것이다. 규칙을 더 추가하기
전에 어떤 회로군이 왜 실패하는지 분리해서 측정할 수 있어야 다시 BLDC 특례 누적
방식으로 돌아가지 않는다.

### 코어 배치·배선 엔진 전환

`src/circuitgen/router.py`에 첫 범용 배선 프리미티브를 구현했다. 격자 A*가 심볼
장애물과 clearance를 피해 직교 경로를 찾고, 각 추가 단자를 기존 경로 트리의
가장 가까운 지점에 연결하는 rectilinear Steiner-tree 근사 방식이다. 경로는 직선
세그먼트로 압축되며 3방향 이상 분기는 junction 후보로 반환한다. 현재는 독립
geometry 단계이며, 다음 게이트는 emitter 통합 전 핀 탈출 구간·기존 와이어 간
clearance·넷별 rip-up/reroute 검증이다.

현재 평가 진입점은 `scripts/bench_general.py`이며 결과는
`out/bench_general/<label>.jsonl`에 저장한다. 토폴로지 관찰기는
`src/circuitgen/topology.py`, 고정 평가 입력은
`data/eval/general_circuit_suite.json`이다.

### 1차 실측

- `topology-baseline`: op-amp/레귤레이터 모두 ERC 또는 기능 계약 실패, 0/2.
- `topology-contract-v2`: 계약을 생성 프롬프트와 재시도에 연결. 잘못된 결과는
  출력 전에 차단됐지만 성공 0/2.
- `topology-contract-v4`: 명시 전압 레일 보존과 요구 역할 기반 결정론적 토폴로지
  수리를 추가한 뒤 op-amp가 KiCad 파이프라인과 피드백 계약을 모두 통과, 1/2.
  레귤레이터는 아직 기능 완전성 게이트에서 차단된다.
- `regulator-diagnostic-v5~v7`: 토폴로지는 완성됐지만 후보의 추가 제어핀과
  한국어 조사에 붙은 `5V를` 인식, 실제 IN/GND 핀 뒤바뀜을 차례로 발견했다.
- `regulator-semantic-pins-v8`: 출력전압 기반 후보 검색, 단순 3핀 우선 랭킹,
  ASCII 전압 경계, 심볼 핀 이름 기반 전원 재배선을 적용해 레귤레이터가
  KiCad 파이프라인과 바이패스 계약을 모두 통과, 1/1.

실패 차단 자체와 성공률을 혼동하지 않는다. `functional-topology` 또는
`functional-completeness`는 안전한 실패이며, 릴리스 성공 점수에는 포함하지 않는다.

### 2차 회로군 실측

`general-wave2-baseline`에서 I2C 센서, 릴레이 구동, Conceptual 폴백은 0/3이었다.
하지만 실패는 다음의 범용 입력 계층 문제로 분해됐다.

- I2C 요구인데 SDA/SCL 없는 아날로그 온도센서가 텍스트 유사도로 선택됨
- flyback diode 요구인데 이름이 비슷한 flyback transformer가 선택됨
- TX/RX/전원 연결을 부품 역할로 추출해 중복 블록을 생성함
- ERC 수리 모델이 기존 센서·수동소자를 새 복사본으로 추가함

이에 실제 핀 capability 필터, transformer/diode 기능군 필터, 연결 pseudo-role 제거,
명시적 Conceptual 카탈로그 우회, 문서상 NC 자동 표시, 수리 중 기존 부품 중복 추가
거부, 수리 후 기능 완전성 재검사를 추가했다. I2C 후보는 실제 Si7050 계열로
교정됐으며, 후속 과제는 풀업 방향과 릴레이 코일 메타데이터 계약이다.

후속 구현에서는 잘못 GND에 연결되거나 한 핀이 열린 풀업 저항을 복제하지 않고
SDA/SCL-논리전원 사이로 재사용한다. 요구 spec이 논리전원을 누락해도 실제 IR의
`+` 전원 넷을 사용한다. 릴레이 후보는 공통 코일 단자 `A1/A2`를 가진 심볼을
우선하며, 기존 일반 다이오드를 해당 코일 양단으로 재배선한다. 그래픽만으로
코일을 추정해야 하는 익명 핀 심볼에는 이 규칙을 적용하지 않는다.

`i2c-supply-aware-v6` 실측에서 Si7050 센서, SDA/SCL 풀업, NC 처리와 KiCad
ERC가 모두 통과해 1/1을 기록했다. 릴레이 v6은 A1/A2가 핀 이름이 아니라 핀
번호인 KiCad 표현 차이로 후보가 제거됐으며, capability 집합에 번호를 포함하도록
수정했다.
